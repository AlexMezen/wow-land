# Инструкция: подключение аналитики (GA4, Meta Pixel, Clarity) и заявок

Этот документ — пошаговая инструкция для владельца сайта. Код уже готов: нужно только
получить **три идентификатора (ID)** и вставить их в указанные места. Программировать не нужно.

---

## Как всё устроено (30 секунд)

Сайт читает 4 «ключа» из файла настроек:

| Ключ                       | Что это                              | Где взять                  |
| -------------------------- | ------------------------------------ | -------------------------- |
| `VITE_GA_ID`               | Google Analytics 4                   | analytics.google.com       |
| `VITE_META_PIXEL_ID`       | Рекламный пиксель Facebook/Instagram | eventsmanager.facebook.com |
| `VITE_CLARITY_ID`          | Записи сессий и тепловые карты       | clarity.microsoft.com      |
| `VITE_ADMIN_PASSWORD_HASH` | Пароль админки (CMS)                 | см. раздел 5               |

Ключи вставляются в файл `.env.local` в корне проекта (рядом с `package.json`).
Пример уже лежит в файле `.env.example`.

**Важно:** ключи действуют на момент сборки сайта. После изменения `.env.local` нужно
пересобрать сайт (`npm run build`) или сделать push в GitHub — деплой пересоберётся сам.

## 1. Google Analytics 4 (GA4) — посещаемость и события

1. Откройте **https://analytics.google.com** и войдите через Google-аккаунт.
2. Нажмите **«Начать измерение»** (или шестерёнка «Администратор» → **«Создать ресурс»**).
3. Название ресурса: например `eLITstroy` → нажмите **«Далее»** и заполните поля о компании
   (можно выбрать любые подходящие варианты) → **«Создать»**.
4. Выберите платформу **«Веб»**.
5. В поле «URL веб-сайта» вставьте адрес сайта (например `https://ваш-домен.ua`),
   название потока: `Сайт` → **«Создать поток»**.
6. На экране появится **«Идентификатор потока данных»** вида `G-XXXXXXXXXX` —
   скопируйте его. Это и есть ваш `VITE_GA_ID`.
7. Откройте файл `.env.local` (если его нет — создайте в корне проекта) и добавьте строку:
   ```
   VITE_GA_ID=G-XXXXXXXXXX
   ```
   (вместо `G-XXXXXXXXXX` — ваш идентификатор)
8. Пересоберите/задеплойте сайт.

**Проверка:** откройте сайт в браузере → в GA4 слева **«Отчёты» → «Реальное время»** —
вы должны увидеть себя как активного пользователя в течение ~30 секунд.

## 2. Meta Pixel (Facebook/Instagram) — ретаргетинг рекламы

1. Откройте **https://eventsmanager.facebook.com** (нужен бизнес-аккаунт Meta; если его нет —
   создайте на **business.facebook.com**).
2. Нажмите **«Подключить источник данных» → «Интернет»**.
3. Название пикселя: например `eLITstroy Pixel` → **«Создать пиксель»**.
4. На шаге «Установить код вручную» НЕ вставляйте код на сайт — он уже встроен.
   Скопируйте **ID пикселя** (15–16 цифр, показан вверху страницы пикселя).
5. Добавьте в `.env.local`:
   ```
   VITE_META_PIXEL_ID=1234567890123456
   ```
6. Пересоберите/задеплойте сайт.

**Проверка:**

- Установите бесплатное расширение Chrome **Meta Pixel Helper** → откройте сайт →
  значок расширения должен показать активный пиксель и событие `PageView`.
- В Events Manager вкладка **«Тестирование событий»** → введите адрес сайта → кликайте
  по кнопкам на сайте и смотрите, как приходят события.

---

## 3. Microsoft Clarity — тепловые карты и записи сессий (бесплатно)

1. Откройте **https://clarity.microsoft.com** и войдите (подойдёт Microsoft / Google / Facebook аккаунт).
2. Нажмите **«Добавить новый проект»** → название: `eLITstroy`.
3. В окне установки выберите **«Вручную установить сторонний код»** — не вставляйте код,
   просто скопируйте **ID проекта** (32 символа, показан в коде установки).
4. Добавьте в `.env.local`:
   ```
   VITE_CLARITY_ID=abcdefghijklmnopqrstuvwxyz12
   ```
5. Пересоберите/задеплойте сайт.

**Проверка:** откройте сайт, полистайте страницу → в Clarity слева **«Записи» (Recordings)** —
через 1–2 минуты появится ваша сессия. Разделы «Тепловые карты» (Heatmaps) заполнятся
после накопления визитов.

## 4. Какие события уже отправляются

Всё подключается автоматически, ничего дополнительно делать не нужно:

| Событие             | Когда срабатывает                                   |
| ------------------- | --------------------------------------------------- |
| `page_view`         | Открытие сайта (GA4/Pixel автоматически)            |
| `cta_click`         | Клик по любой кнопке-призыву (шапка, герой, и т.д.) |
| `calculator_change` | Изменение параметров калькулятора                   |
| `form_submit`       | Отправка формы заявки                               |
| `messenger_select`  | Клик по плавающим кнопкам Telegram/WhatsApp/Viber   |
| `language_change`   | Переключение языка UA/EN                            |

Эти же события видны в GA4 (**Отчёты → Реальное время → Счётчик событий по имени**),
в Meta Events Manager и в Clarity.

## 5. Пароль админки (CMS)

По умолчанию пароль: `wow-admin` (работает, пока не задан `VITE_ADMIN_PASSWORD_HASH`).

Чтобы установить свой пароль:

1. Придумайте пароль, например `MoyParol2026!`.
2. Получите его SHA-256 хеш. Самый простой способ — откройте консоль браузера (F12),
   вставьте и выполните (подставив свой пароль):
   ```js
   crypto.subtle
     .digest("SHA-256", new TextEncoder().encode("MoyParol2026!"))
     .then((b) =>
       console.log(
         [...new Uint8Array(b)]
           .map((x) => x.toString(16).padStart(2, "0"))
           .join(""),
       ),
     );
   ```
3. Скопируйте полученные 64 символа и добавьте в `.env.local`:
   ```
   VITE_ADMIN_PASSWORD_HASH=полученный_хеш
   ```
4. Пересоберите/задеплойте сайт. Теперь вход в CMS — по вашему паролю.

## 6. Заявки с сайта: куда они попадают

Зависит от способа размещения сайта:

- **На своём VPS** (см. `DEPLOY-VPS.MD`) — заявки **автоматически** сохраняются на сервере
  (`data/leads.json`) и сразу видны во вкладке **«Заявки»** CMS с любого устройства.
  Ничего дополнительно подключать не нужно.
- **На статическом хостинге** (GitHub Pages) — заявки сохраняются в браузере посетителя
  и видны во вкладке «Заявки» CMS только в том браузере, где отправлены. Для приёма заявок
  от реальных посетителей на статическом хостинге понадобится доработка разработчика
  (внешний endpoint, раздел 7) — на VPS этого не требуется.

## 7. (Только для статического хостинга) Приём заявок в Google Таблицу — 10 минут, бесплатно

> Если сайт работает на вашем VPS — этот раздел не нужен, заявки уже сохраняются на сервере.

1. Создайте таблицу: **https://sheets.google.com** → «Пустая таблица» → назовите `Заявки сайта`.
2. В меню таблицы: **«Расширения» → «Apps Script»**.
3. Удалите содержимое редактора и вставьте код:

   ```javascript
   function doPost(e) {
     const data = JSON.parse(e.postData.contents);
     const sheet =
       SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Leads") ||
       SpreadsheetApp.getActiveSpreadsheet().insertSheet("Leads");
     if (sheet.getLastRow() === 0) {
       sheet.appendRow([
         "id",
         "date",
         "name",
         "contact",
         "interest",
         "messenger",
         "locale",
       ]);
     }
     sheet.appendRow([
       data.id,
       new Date(data.ts),
       data.name,
       data.contact,
       data.interest,
       data.messenger,
       data.locale,
     ]);
     return ContentService.createTextOutput(
       JSON.stringify({ ok: true }),
     ).setMimeType(ContentService.MimeType.JSON);
   }

   function doGet() {
     const sheet =
       SpreadsheetApp.getActiveSpreadsheet().getSheetByName("Leads");
     const rows = sheet ? sheet.getDataRange().getValues() : [];
     const header = rows.shift() || [];
     const leads = rows.map((row) => ({
       id: String(row[0]),
       ts: new Date(row[1]).getTime(),
       name: String(row[2]),
       contact: String(row[3]),
       interest: String(row[4]),
       messenger: String(row[5]),
       locale: String(row[6]),
     }));
     return ContentService.createTextOutput(JSON.stringify(leads)).setMimeType(
       ContentService.MimeType.JSON,
     );
   }
   ```

4. Нажмите **«Развернуть» → «Новое развёртывание»** → тип: **«Веб-приложение»**:
   - «Выполнять как»: **меня**
   - «Кто имеет доступ»: **все**
     → **«Развернуть»** → разрешите доступ (аккаунт → «Дополнительно» → «Перейти» → «Разрешить»).
5. Скопируйте **URL веб-приложения** (заканчивается на `/exec`) — он понадобится разработчику
   для подключения приёма заявок (в CMS на статическом хостинге поле endpoint не выводится).

## 8. Публикация ключей на GitHub Pages

Чтобы ключи попали на «боевой» сайт (деплой через GitHub Actions):

1. Откройте репозиторий на GitHub → **Settings → Secrets and variables → Actions**.
2. Нажмите **«New repository secret»** и создайте по очереди:
   - `VITE_GA_ID` — значение из раздела 1
   - `VITE_META_PIXEL_ID` — из раздела 2
   - `VITE_CLARITY_ID` — из раздела 3
   - `VITE_ADMIN_PASSWORD_HASH` — из раздела 5 (по желанию)
3. Workflow деплоя (`.github/workflows/deploy.yml`) уже настроен передавать эти секреты
   в сборку. Сделайте любой push (или **Actions → Deploy to GitHub Pages → Run workflow**),
   и сайт пересоберётся уже с аналитикой.
